## 1. Executive Summary & The Identified Research Gap

Automated incident remediation and Automated Program Repair (APR) represent two historically distinct research disciplines:
1. **Classic & LLM-Based APR:** Focuses predominantly on offline benchmarks (e.g. Defects4J, QuixBugs), generating code patches evaluated solely against offline test suites. In this regime, passing the visible test suite is assumed to be the definition of repair success.
2. **AIOps & Autonomic Computing:** Focuses on microservice observability, anomaly detection (Prometheus, distributed tracing), and container orchestration (Kubernetes restarts, auto-scaling, canary traffic routing), treating application binaries as black boxes.

### The Research Gap:
**Neither discipline provides a risk-aware, execution-gated framework for safely deploying AI-synthesized code patches into live running microservices.**
- Traditional APR systems suffer from the **patch overfitting crisis**: patches frequently satisfy the visible test asserting a bug while silently breaking unasserted requirements, corrupting peripheral APIs, or injecting security vulnerabilities.
- Standard continuous deployment pipelines rely on the "full regression suite" as the ultimate quality gate. As AutoImmune empirically proves, **passing a full regression test suite is statistically insufficient**: 23.4% of regression-passing patches introduce static security violations or breach sensitive infrastructure boundaries.
- Full human review ("review-all" policy B0) introduces severe operator fatigue and prolonged MTTR (hours to days), negating the real-time recovery benefits of automated self-healing.

AutoImmune bridges this gap by introducing a **hybrid, non-agentic execution pipeline**: deterministic validation gates (V0–V3), multi-dimensional risk tiering (`AUTO_APPLY`, `ESCALATE`, `REJECT`), and automated canary rollback for microservices.

## 2. In-Depth Literature Review Across Core Dimensions

### 2.1 Classic Automated Program Repair & The Overfitting Crisis
- **Le Goues et al. (2012, IEEE TSE)** introduced *GenProg* [10.1109/TSE.2011.104], demonstrating genetic programming for automated repair without formal specifications. GenProg demonstrated that stochastic search could find plausibly passing variants.
- **Smith et al. (2015, ESEC/FSE)** published the landmark study *"Is the cure worse than the disease? Overfitting in automated program repair"* [10.1145/2786805.2786825], proving that generate-and-validate repair systems overwhelmingly produce patches that overfit the test suite—often by deleting functionality or hardcoding return values.
- **Qi et al. (2015, ISSTA)** demonstrated in *"An analysis of patch plausibility and correctness"* [10.1145/2771783.2771791] that the vast majority of test-passing patches generated by GenProg, RSRepair, and AE were functionally invalid when tested against independent evaluations.
- **Long & Rinard (2016, POPL)** developed *Prophet* [10.1145/2837614.2837617], learning probabilistic models of correct code from human repositories to rank candidate patches and mitigate overfitting.
- **Xiong et al. (2017, ICSE)** presented *ACS* [10.1109/ICSE.2017.45], synthesizing precise conditional guards to achieve high repair precision on Defect4J benchmarks.
- *Relationship to AutoImmune:* AutoImmune takes the overfitting crisis as an axiomatic reality. Instead of assuming pre-deployment tests prove correctness, AutoImmune couples multi-stage test gates with static security analysis (Semgrep V3), diff scope restrictions, and post-deployment canary observation.

### 2.2 LLM-Powered Program Repair & Synthesis
- **Xia, Wei & Zhang (2023, ICSE)** evaluated pre-trained language models in *"Automated Program Repair in the Era of Large Pre-trained Language Models"* [10.1109/ICSE48619.2023.00129], demonstrating that deep models significantly outperform genetic and template-based APR on single-hunk repairs.
- **Xia & Zhang (2024, ISSTA)** introduced *ChatRepair* [10.1145/3650212.3680323], utilizing conversational feedback loops to prompt ChatGPT with compiler and test feedback.
- **Jin et al. (2023, ESEC/FSE)** developed *InferFix* [10.1145/3611643.3613892], integrating static analysis (Facebook Infer) with LLM retrieval to repair memory and concurrency bugs.
- *Relationship to AutoImmune:* AutoImmune establishes strict boundaries around the LLM: **the model is restricted exclusively to diagnosis and one-shot patch generation**. In contrast to multi-agent loops that risk prompt injection and runaway execution, AutoImmune delegates all validation, compilation, and security scanning to deterministic, air-gapped containers. Furthermore, AutoImmune provides a vital negative result: open-weights code models (Qwen2.5-Coder 1.5B/7B) achieve 0.0% verified repairs on multi-layered enterprise microservice faults without iterative refinement.

### 2.3 Security Vulnerabilities in AI-Synthesized Code
- **Pearce et al. (2022, IEEE S&P)** published *"Asleep at the Keyboard? Assessing the Security of GitHub Copilot's Code Contributions"* [10.1109/SP46214.2022.9833571], demonstrating that approximately 40% of code snippets generated by Copilot in security-sensitive contexts contain exploitable Common Weakness Enumerations (CWEs).
- **Zhang et al. (2023, IEEE TDSC)** investigated *"Pre-trained Model-based Automated Software Vulnerability Repair"* [10.1109/TDSC.2023.3308897], highlighting that LLM patches intended to fix security bugs often introduce subtle new vulnerabilities.
- *Relationship to AutoImmune:* AutoImmune explicitly treats the LLM as an **untrusted, adversarial synthesizer**. Gate V3 executes Semgrep AST analysis inside an isolated container, successfully intercepting SQL string concatenation and command execution before any patch can reach production.

### 2.4 Autonomic Computing & Microservice Incident Remediation
- **Kephart & Chess (2003, IEEE Computer)** formulated the foundational *"Vision of Autonomic Computing"* [10.1109/MC.2003.1160055], defining the MAPE-K (Monitor-Analyze-Plan-Execute over shared Knowledge) loop.
- **Zhou et al. (2021, IEEE TSE)** conducted the extensive study *"Fault Analysis and Debugging of Microservice Systems"* [10.1109/TSE.2018.2887384], categorizing real-world microservice defects and highlighting the inadequacy of manual debugging.
- **Chen et al. (2014, IEEE INFOCOM)** introduced *CauseInfer* [10.1109/INFOCOM.2014.6848128], inferring hierarchical causality across distributed tracing paths.
- *Relationship to AutoImmune:* AutoImmune operationalizes the MAPE-K loop for cloud microservices: Prometheus and HTTP health probes (Monitor), root-cause localization (Analyze), LLM patch drafting (Plan), and containerized validation with canary shifting (Execute).

### 2.5 Human-in-the-Loop & Operator Maintainability
- **Fry, Landau & Weimer (2012, ISSTA)** conducted *"A Human Study of Patch Maintainability"* [10.1145/2338965.2336775], demonstrating that human engineers often struggle to differentiate between machine-generated and human-written patches.
- **Tao et al. (2014, ESEC/FSE)** evaluated *"Automatically Generated Patches as Debugging Aids"* [10.1145/2635868.2635873], finding that machine-generated patches help developers localize bugs even when the patch itself is not fully correct.
- *Relationship to AutoImmune:* AutoImmune rejects the binary choice between fully autonomous deployment and manual review. Candidates flagged as medium risk (`ESCALATE`) pause the pipeline and render a dedicated terminal review card presenting the diff, risk tier, and reasons, guaranteeing that zero high-risk changes proceed without explicit operator consent.

## 4. Distinct Novelty Claims & Contributions

1. **Empirical Disproof of Regression-Test Sufficiency:** Demonstrating through paired McNemar tests ($\chi^2 = 9.0909, p = 0.002569$) that full regression suites (V2) admit 23.4% of hazardous patches containing static security vulnerabilities or configuration breaches.
2. **Deterministic, Air-Gapped Sandbox Architecture:** Enforcing physical network isolation (`--network none`), dropped Linux capabilities, and read-only cache mounts to eliminate prompt injection and sandbox poisoning.
3. **Multi-Tier Risk Decision Engine:** Combining gate evidence, diff line limits, single-file locality, path allowlists, and multi-sample diagnosis agreement to partition patches into `AUTO_APPLY`, `ESCALATE`, and `REJECT`.
4. **Closed-Loop Runtime Defense:** Proving that post-deployment canary health monitoring catches algorithmic performance bugs that pass all pre-deployment gates, restoring baseline service health in 5.0 seconds.
5. **Transparent Negative Results:** Disclosing that local open-weights code LLMs achieve 0.0% verified semantic correctness on microservice faults, demonstrating why deterministic validation gates are essential.
