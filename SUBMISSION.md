## Folder map
| Folder | Contents |
|---|---|
| `app/` | The Java 17 / Spring Boot "order-service" being healed |
| `faults/F01, F04, F06/` | Seeded faults: description, injection diff, target test, scripted candidate patches, oracle labels (`candidates/labels.json`). Hidden oracle tests (`hidden_tests/`) are kept out of git and out of the sandbox |
| `pipeline/` | Python orchestrator: detector, providers (LLM live/replay; rule-based diagnosis; scripted hand-built patches, never AI), Docker sandbox gates, decision engine, deployment and rollback, evidence recording, provenance. In rule mode, incidents without a stack trace (F04, F06) take the diagnosed file from `faults/<id>/fault.json` (oracle localisation, flagged `oracle_localisation: true`; never counted in the localisation hit rates, which cover live LLM diagnoses only) |
| `config/decision.yaml` | The main thresholds for the decision engine and health window. A few constants stay in code: the high-severity set (`pipeline/decide.py`) and some timeouts (5 s health request and 3x suspension factor in `pipeline/observe.py`, 120 s startup in `pipeline/deploy.py`). Expected probe values are in `config/probes.yaml` |
| `tests/` | 249 automated tests (16 need Docker) |
| `results/` | Not tracked in git. Generated tables (`*.csv`, `pilot_report.md` from `analyse.py`), the dashboard (`tools/make_dashboard.py`) and oracle labels (`oracle_report.jsonl` from `tools/oracle.py`). `evidence.jsonl` holds one raw row per candidate in each recorded run; the gate results of four incomplete or pre-S0 runs exist only in `runs/` (see `results/runs.csv`) |
| `runs/<run_id>/` | Not tracked in git. Raw artifacts of every pipeline run (incident, diagnosis, patches, gate logs, decisions, approvals, deployments, rollbacks) |
| `cache/` | Recorded LLM requests and responses (40 entries: qwen2.5-coder:7b 16, qwen2.5-coder:1.5b 12, openai/gpt-oss-120b 12), kept as an audit record. Only the 12 gpt-oss-120b entries use the current cache-key version; no replay-mode run has completed |
| `docs/` | Project report, audit (`audit/`), demo script, experiment protocol and data split, fault catalog, label-adjudication sheet, phase notes, runbook, plans |
| `tools/` | Independent oracle (`oracle.py`), dashboard generator (`make_dashboard.py`), healthy-load watch (`healthy_watch.py`) and load generator (`load.py`), audit manifest tool (`audit_baseline.py`), and helpers: deployment demo, candidate gating, diff generation, LLM smoke test, CRA research prototype (`research/`) |

## Run it (Windows)
Needs Python 3.12 (the `py` launcher), Git, Docker Desktop, and network access for first setup. The gates run Maven
offline (`--network none`), so they also need the images `maven:3.9-eclipse-temurin-17` and `semgrep/semgrep:1.100.0`
(the Docker tests also use `alpine`), and the Docker volume `autoimmune-m2` filled once with a Maven repository at
`/m2/repository` by a networked `mvn` run; no script in the repo does this. Without that volume the gates end in tool errors and the 16 Docker tests are skipped.
```
py -3.12 -m venv .venv
.\.venv\Scripts\pip install -r requirements.lock
.\.venv\Scripts\python -m pytest -rs          # 249 tests; the 16 Docker tests skip without the setup above
.\.venv\Scripts\python analyse.py --check     # results/ match the raw evidence (run before any new pipeline run)
.\.venv\Scripts\python -m pipeline run --fault F06 --diag-mode rule --patch-mode scripted
.\.venv\Scripts\python analyse.py             # regenerate results/ to include the new run
```
A new pipeline run appends rows to `results/evidence.jsonl` and adds a `runs/<id>/` folder. Until `analyse.py` is
rerun, `analyse.py --check` reports STALE (exit 1).

The `.venv` folder is left out of the repository (`.gitignore`) and should not be copied into an archive: a virtual
environment stores absolute paths to its own folder and to the Python install, so it breaks when copied or moved.
Create a fresh one with the commands above.
