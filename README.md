# AutoImmune

AutoImmune is a B.Tech research prototype: a hybrid self-healing pipeline for a Java Spring Boot service (order-service). It observes the service, detects and diagnoses a fault, drafts three candidate patches, and validates each one in a Docker sandbox through four gates (V0 compile, V1 target test, V2 full test suite, V3 new Semgrep findings). A rule-based risk tier then decides to REJECT, ESCALATE or AUTO_APPLY. Auto-applied patches are deployed, watched over a health window, and either promoted or rolled back, with evidence recorded for every candidate. The research question is how much execution evidence lets an AI-generated patch deploy without human review, and what each gate catches.

## Results (pilot, 2026-11-09)

> Every number comes from `results/pilot_report.md`, generated by `python analyse.py` (checked by
> `python analyse.py --check`); independent labels come from `tools/oracle.py`. These are pilot counts on three seeded
> faults, not general safety claims. Full write-up: [docs/PROJECT_REPORT.md](docs/PROJECT_REPORT.md).
> Integrity audit: [docs/audit/AUDIT_BASELINE.md](docs/audit/AUDIT_BASELINE.md).

- **Full loop, with provenance:** on F06, F01 and F04 the fault was detected 5–6 s after injection, gated, decided,
  deployed (smoke-tested side by side, image ID verified) and promoted or rolled back. There was no false alarm in
  300 s of healthy traffic.
- **Independent oracle:** hidden specification tests, the full suite, a performance test and a security probe label
  every candidate offline. The pipeline never sees them. Two-person review of the labels is pending.
- **Hand-built patches (32 evaluations, 26 unsafe by oracle):** unsafe patches that would be auto-applied fell from 20
  (target test only) to 13 (plus full suite) to 7 (full AutoImmune policy). 0 of 6 correct patches were rejected.
- **Real AI repair:** `openai/gpt-oss-120b` diagnosed F06, wrote a fix that passed all gates, and the fix was
  **deployed and promoted automatically**. The oracle labels it correct.
- **Key finding:** under the full policy, **2 of 5 auto-applied AI patches were wrong** per the oracle:
  - F01: the patch only rejects `null`, so blank names still slip through.
  - F04: after a misdiagnosis, the patch forces the health check to UP. The correct config fix was escalated and never
    reached a human.

  Passing tests and health checks is not proof of correctness.
- **Rollback:** a planted slow patch passed every gate and the side-by-side smoke test, then breached the latency
  limit and was rolled back automatically in 5.1 s, with the restored image ID verified
  (`runs/f06-rule-scripted-20261108t201808z`; staged demo, never counted as a real catch).
- **Human review:** real `human_cli` approve and reject decisions are recorded on the escalated F04 config patch.
- **Limits:** three development faults, no held-out set, small samples. Policy differences are not statistically
  established.

## Setup and tests

Needs Python 3.12 and Docker Desktop running (the gates use the `maven:3.9-eclipse-temurin-17` and
`semgrep/semgrep:1.100.0` images). Do not copy a `.venv` between machines; create it fresh:

```
py -3.12 -m venv .venv
.\.venv\Scripts\pip install -r requirements.lock
.\.venv\Scripts\python -m pytest -rs              # full suite (~10 min with Docker)
.\.venv\Scripts\python -m pytest -m "not docker"  # fast suite, no Docker
```

## Regenerating results

```
.\.venv\Scripts\python analyse.py           # rewrites results/*.csv and pilot_report.md (old ones archived)
.\.venv\Scripts\python analyse.py --check   # exit 1 if results/ is stale
.\.venv\Scripts\python tools\audit_baseline.py --out docs\audit\baseline_manifest.json
```
